# Spec: czx-beauty 电影推荐网站

## Problem Statement

用户（常大人）正在学习机器学习/深度学习，希望构建一个**企业级架构的电影推荐网站**来实践所学。核心诉求：网站通过用户点击不同电影来学习其喜好，从而提供更好的个性化推荐。用户重在学习「项目如何构建」（分层架构、前端/后端/数据库协作、算法落地、工程化），而非仅仅跑通一个 demo。数据集为 MovieLens ml-latest-small（10 万评分 / 9724 电影 / 610 用户），放在本机 Downloads。

## Solution

构建一个全栈电影推荐网站 `movie-recommender`（GitHub 仓库名 `czx-beauty`），采用**混合推荐路线**：

- **交互层**：用户注册登录后，在首页电影流中点击电影卡片（隐式反馈信号 = 感兴趣），也可进详情页给 1-5 星显式评分
- **推荐层**：冷启动用历史评分数据（热门/高分兜底）；用户产生行为后，后台定时（每 5 分钟）重算个性化推荐（ItemCF 协同过滤），接口读缓存返回
- **架构层**：FastAPI（后端）+ React/Vite（前端）+ PostgreSQL（数据库）+ uv（虚拟环境），企业级分层，推荐引擎抽象为可替换接口
- **学习层**：Git 全程版本管理，最终推到用户 GitHub 仓库，README 含架构图与启动步骤

## User Stories

1. 作为用户，我想要注册账号，以便系统记住我的身份和喜好
2. 作为用户，我想要登录已有账号，以便继续之前的推荐和喜好记录
3. 作为用户，我想要在首页看到电影推荐流，以便发现感兴趣的影片
4. 作为用户，我想要点击电影卡片表达兴趣，以便系统学习我的喜好
5. 作为用户，我想要在电影详情页看到简介/类型/评分，以便决定是否观看
6. 作为用户，我想要给电影打 1-5 星评分，以便显式表达喜好程度
7. 作为用户，我想要搜索电影，以便直接找到特定影片
8. 作为用户，我想要按类型（科幻/喜剧/爱情等）筛选电影，以便缩小浏览范围
9. 作为用户，我想要查看「我的喜好」页，以便了解系统学到了什么
10. 作为用户，我想要看到推荐随我的点击行为更新，以便体验「学习」效果
11. 作为新用户（无历史行为），我想要看到合理的热门/高分推荐，以便冷启动不尴尬
12. 作为用户，我想要退出登录，以便保护账号安全
13. 作为学习者，我想要看到项目有清晰的分层结构（backend/frontend/docs），以便理解企业级架构
14. 作为学习者，我想要 API 有自动文档（Swagger），以便调试和理解接口
15. 作为学习者，我想要推荐引擎是抽象接口，以便将来替换算法（向量召回/双塔）而不动上层
16. 作为学习者，我想要数据自动导入数据库（幂等），以便一键起步
17. 作为学习者，我想要每个阶段 Git commit，以便看到完整成长轨迹
18. 作为学习者，我想要项目能推到 GitHub 仓库，以便作为作品集展示

## Implementation Decisions

**技术栈**（ADR-0002）：FastAPI + React/Vite + PostgreSQL；uv 建虚拟环境；SQLAlchemy ORM；JWT 认证。

**混合推荐**（ADR-0001）：点击为隐式反馈（评分二值化 >=4 视为喜欢）；历史评分用于冷启动与算法验证。

**推荐引擎 v1**（ADR-0004）：ItemCF 协同过滤，评分二值化 + 物品相似度预计算；通过统一接口 `RecommendationEngine` 封装，预留替换位。

**更新机制**（ADR-0003）：行为事件（点击/评分）写入数据库；APScheduler 每 5 分钟重算 → 写推荐缓存表；API 只读缓存返回。

**数据模型**：User（注册登录）、Movie（标题/类型）、Rating（1-5 星）、ClickEvent（点击事件）、RecCache（用户→推荐列表）。

**导入**：启动时自动从 CSV 导入（幂等），脚本独立保留可手动重跑；tags.csv/links.csv 不导入（学习阶段只建核心表）。

**页面**：登录/注册、首页推荐流、电影详情、搜索、类型筛选、我的喜好。

**Git/GitHub**：仓库 `czx-beauty`；.gitignore 排除虚拟环境与密钥；每阶段 commit。

## Testing Decisions

- **测试原则**：只测外部行为（API 响应），不测实现细节；推荐引擎用独立脚本验证输出合理性（给已知用户出 Top-10，抽查相似电影是否同类）
- **模块**：
  - 后端 API 冒烟测试（health、注册/登录流程、推荐接口返回 200 且结构正确）
  - 数据导入脚本验证（幂等：跑两遍不重复）
  - 推荐引擎离线验证（相似度矩阵维度、Top-10 输出、已看过的电影被排除）
- **先例**：本项目为全新仓库，无既有测试；测试采用 pytest + FastAPI TestClient

## Out of Scope

- 真实点击流数据（数据集无「点击但不评分」行为，用评分二值化模拟）
- 深度学习推荐模型（双塔/向量召回为预留方向，不在本期实现）
- 第三方登录（OAuth）、评论/关注/管理后台
- 部署上线（本期仅本地运行 + GitHub 托管代码）
- 大规模性能优化（数据量 10 万级，单机足够）
